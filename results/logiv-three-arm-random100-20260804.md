# Base / Shadow LOGIV / Full LOGIV：100 个随机仿真 case 三臂配对结果

## 结论

在完全相同的 100 个随机 case 上，**Base = 88/100，Shadow LOGIV = 88/100，Full LOGIV = 82/100**。主动干预相对 Base 的观测差值是 **-6 个百分点**；10,000 次任务分层配对 bootstrap 的 95% 区间为 **[-14, +2] 个百分点**，McNemar 精确双侧检验 `p=0.2632`。因此这批结果既不支持“主动 LOGIV 更好”，点估计反而更差。

Full LOGIV 救回 7 个 Base 失败 case，但同时使 13 个 Base 成功 case 退化，净损失 6 个。Shadow 是只读臂，100/100 与 Base 的动作轨迹、步数和结果完全一致；它的作用是检查拓扑状态，不应产生成功率提升。

## 拓扑与前置条件状态

- Shadow 的初始拓扑在每个 episode 内保持固定：100/100 条轨迹的 `graph_hash` 和 `graph_version` 均未改变；10 个任务各自的节点数、边数、宽度结构在 10 个随机初态中一致。节点参数会绑定到具体初态，因此原始 graph hash 按 episode 不同。
- 共触发 27,466 次实时检查，写入 26,567 个状态快照，覆盖率 **96.73%**。899 次缺口全部来自严格 grounding/trace coverage，回调、provenance、snapshot 和事件跟踪错误均为 0；没有把无法判定的状态强行写成真。
- 状态观测计数：`COMPLETED=39,728`、`READY=22,175`、`BLOCKED=46,069`、`PRECONDITION_UNKNOWN=297`；显式 UNKNOWN 出现在 10/100 个 case。
- 在终态快照与仿真终止步一致的 99 个 case 中，GOAL 状态相对原生仿真结果为 TP=59、FN=29、TN=10、FP=1，准确率 **69.70%**、成功召回率 **67.05%**。它明显偏向假阴性，尚不适合作为硬控制门。另有 1 个 case 因最后一步 grounding 缺口而不计入。
- 主要实时状态变化为 `BLOCKED→COMPLETED=203`、`BLOCKED→READY=156`、`READY→BLOCKED=257`、`READY→COMPLETED=57`；说明状态确实随观测更新，而图结构本身没有被重写。

## 主动干预行为

Full LOGIV 共执行 238 次物理尝试、45 次修复、141 次图安装和 166 次 VAL 调用；产生 190 个 committed、40 个 failed、8 个 unknown receipt。门控拒绝为：前置条件 1、效果 40、终态目标 4。平均步数从 Base 的 273.66 增至 323.01。

20 个 Full 失败的终止原因：`POST_STOP_GROUNDING_FAILURE=8`、`BUDGET_EXHAUSTED=6`、`NO_CERTIFIED_REPAIR_WITHIN_BUDGET=4`，其余为成功。结合 Shadow 的 29 个终态假阴性，当前最需要解决的是 simulator grounding 与原生任务判定不一致，而不是继续增加干预规则。

因此当前合理选择是：**保留 Shadow 做诊断，不启用 Full 做默认控制**。下一轮只应针对 grounded official goal/effect 与 LIBERO native success 的一致性做单点修正，再用同一 manifest 复跑；在此之前声称“基于前置条件的干预提高准确率”没有证据。

## 证据边界

这是 `development_only`、`METADATA_ASSISTED`、simulator/oracle-grounded 的随机开发评估，不是 held-out 或 API-VLM 结果。Full−Base 的置信区间跨 0；结论应表述为“本批次未观察到干预收益，点估计为负”，不能表述为已证明永久劣于 Base。
